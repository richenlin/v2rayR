# 统一规则编译与执行引擎

日期：2026-11-12

## 目标与语义

接入方式只有系统代理、手动端口、TUN。PAC 是规则数据来源；兼容旧 pac 请求并转换为系统代理。策略独立：规则、全局代理、全部直连。规则模式严格执行「自定义规则（数据库顺序）→ PAC 分组（文件顺序，各组先直连后代理）→ 默认直连」，首次命中生效。全局与直连不执行业务规则。节点自身、防回环和 TUN DNS 接管是基础设施例外，不能把一般私网直连放在自定义规则之前。

## 架构与性能

Rust 控制面在连接/重新连接时读取规则快照、规范化 PAC、去重、检查能力，生成内核无关的有序计划。数据面复用 Xray、sing-box、Mihomo 原生匹配，不引入每连接 Rust RPC 或额外转发。精确域名、后缀与 CIDR 保留独立语义，不能按类型重排。去重只删除同类型同目标的后续规则，保留首条动作；不会推断跨类型遮蔽关系。

Xray/sing-box 将连续、同类型同动作域名规则合并成原生数组，减少大型 PAC 的路由对象数量，不能跨越异动作规则。Mihomo 使用原生有序规则，保留其适配器差异，不承诺与另外两种内核同等性能。编译过程使用散列表去重，预期线性增长。无规则内容变化时不需要会话内反复编译；本期不增加跨会话缓存与独立匹配索引，避免缓存一致性复杂度。

PAC 的偶数列为直连、奇数列为代理，保持已有数据语义；没有下载列表时视为空列表，未命中直连。损坏或超限的已有缓存应报告错误，不静默替换为空列表。下载仅接收受限 JSON 数据，不执行远端 JavaScript。

## 接入和能力

系统代理固定指向本地 HTTP/SOCKS 入口，完整规则由内核执行；不再让浏览器 PAC 与内核分两次决策。手动端口使用同一计划。旧 PAC 服务仅保留兼容代码，不作为新会话入口。规则模式不下发系统绕过列表，避免绕过自定义规则；全局模式也不使用业务绕过项。

macOS TUN 继续由可信 helper 执行规则，内核仅提供代理出口。将 PAC 编译为有序后缀规则并交给 helper；严格遵守现有 256 条/128 KiB 协议限制，不扩大特权协议。规则类型不支持或超过限制时整份计划回退全局，明确提示原因，不截断规则。其他平台 TUN 当前全局兜底。TUN 全部直连暂按全局兜底，保留用户意图；不能宣称已执行直连。

指定应用身份规则仅在支持的 TUN 规则计划生效。普通入口无法可靠归属进程，不扩大应用规则作用范围，保留记录并在连接状态与规则列表标示未生效。旧 process 类型也不能冒充可信应用身份；普通入口不下发不可识别的来源条件。

## 状态、更新和兼容

连接状态同时提供 requestedPolicy、实际 policy 和 routingWarnings。保存用户选择，不能将平台回退写回偏好。旧 pac 模式转换为 system-proxy。规则变更及 PAC 更新采用「保存后下次连接生效」，界面必须明确这一点；不伪装成热更新。本期不实现无中断配置切换，继续使用已有先校验再启动与连接失败清理机制。后续若增加热更新，应额外实现验证后切换、失败保留旧会话的事务，不直接复用当前先断开再连接机制。

旧 Geo/广告规则开关不再在普通会话自动注入隐藏的路由；用户需通过显式自定义规则表达其优先级。保留数据避免破坏升级兼容。UI 提示该变化。

## 验收

1. 各内核规则未命中默认直连，全局只代理、直连只直连。
2. 自定义与 PAC 冲突时自定义获胜；PAC 分组顺序保持；域名后缀不误匹配 evil-example.com。
3. 合并前后有序规则决策等价，包含相邻异动作、跨类型重叠和重复项。
4. 普通模式有应用规则仍可连接，但清晰报告未生效；Windows TUN 回退可见，切换方式保留策略偏好。
5. PAC 缺失、损坏、超限，TUN 类型/容量超限均有确定行为。
6. 运行工作区测试、前端类型检查、构建和生命周期回归；可用内核二进制做配置校验。
7. 基准覆盖 1k/10k/50k PAC 域名，记录编译耗时、路由对象/配置体积。真实连接 P50/P95/P99、吞吐、RSS、DNS 与 Windows 安装验收需原生测试，不能用编译基准或单元测试替代。

## 交付边界

本期交付规则编译、内核适配、降级反馈及回归证据。不将 Windows 实机、macOS TUN 安装包升级、完整数据面性能验收或热更新标记为完成。

## 匹配元数据与 DNS 边界

IP/CIDR 匹配已知目的 IP（含客户端直接提供的 IP），不为路由匹配额外触发 DNS 查询。域名目标通过域名规则匹配；最终建立直连时的解析不属于第二轮路由。Xray 使用 AsIs，Mihomo IP 规则使用 no-resolve，避免第二轮解析让优先级产生跨内核差异。Xray sniffing 使用 routeOnly，保留原始目的地址。此选择避免规则匹配被网络 DNS 延迟阻塞；不承诺“仅提供域名时 CIDR 也能匹配其解析结果”。如未来增加按需解析，必须作为显式选项并为所有适配器补充等价实现及 DNS 失败语义。

启动就绪：全局代理（含 TUN 的代理出口）保留代理 HTTP 探测；普通规则/直连模式只以配置校验与本地监听就绪为启动判据，避免合法阻断规则或不可达的直连探测地址阻止接管。该状态不证明远端代理节点可用，节点质量仍需单独探测。规则和 PAC 编辑不热更新。

参考：[Xray 路由策略](https://xtls.github.io/config/routing.html)、[sing-box 路由规则](https://sing-box.sagernet.org/configuration/route/rule/)。本仓库实际校验版本与证据见实施报告，文档不是实机验收替代品。

## PAC 默认直连精简

PAC 是最低优先级规则段，后面只有默认直连，因此可在有序去重后删除不再影响结果的直连项。自定义规则不参与该删除，原始 PAC 缓存也不修改。

从尾向前扫描，用域名标签边界的后缀索引记录后续非直连规则。若某条直连域名与后续代理/阻断域名存在相同、父域或子域关系，则保留；不存在交集时删除。该保守优化避免逐条直连与全部代理规则进行两两比较，并保持首次命中语义。纯直连 PAC 可精简为空列表。

例如 `safe.example.com → DIRECT` 后跟 `example.com → PROXY` 时必须保留直连例外；`example.com → DIRECT` 后跟 `child.example.com → PROXY` 也必须保留。`unrelated.cn → DIRECT` 与后续 `example.com → PROXY` 无交集，可以删除。`evil-example.com` 不属于 `example.com` 的子域。

精简结果统一供普通入口和 TUN 使用，并在 TUN 256 条/128 KiB 容量检查之前执行。容量依据精简后的规则计算，无法安全删除的例外仍计入容量。

## 跨内核能力及接管边界（审查补充）

本节限定前文“统一语义”的适用范围：统一的是有序规则和动作；能否取得相同的域名、IP、进程元数据，依赖接入方式和内核。

- 普通 HTTP/SOCKS 入口由客户端提供域名时可直接匹配域名规则。只有 IP 时，Xray/sing-box 依赖已开启的嗅探及可识别协议；当前 Mihomo 适配器未配置 sniffer，不能承诺相同行为。
- `.example.com` 与 `example.com` 在本产品的域名后缀规则中均规范化为“自身及子域”，不提供 sing-box 前导点的仅子域语义。国际域名需输入 Punycode。
- “直连解析不属于第二轮路由”仅指业务连接不因直连解析结果重新决策。Xray freedom 的 UseIP 使用内置 DNS，其查询流量本身可能受路由影响；sing-box 使用 dns-local。DNS 查询出口、解析来源不能宣称跨内核一致。
- TUN helper 未配置 FakeIP 或反向 IP→域名映射；域名匹配依赖嗅探，不可嗅探流量只能使用已知 IP 等条件。
- **TUN 接管范围例外**：helper 在 OS 路由层排除节点地址、127/8、10/8、172.16/12、192.168/16、169.254/16、::1/128、fe80::/10、fc00::/7。这些目标不会进入业务规则匹配，全局模式也不覆盖。本期保留该部署行为，每个 TUN 计划明确给出提示；它是当前能力限制，不代表用户私网规则已生效。更改接管范围须另做管理员安装态网络与恢复验证。
- PAC 代理条目超过剩余 256 条预算时，TUN 必然整体回退全局。常见大型 PAC 的代理条目就会超限，这是当前常见使用场景的限制，不是偶发边缘情况。直连精简不能消除这个限制。
- Mihomo 当前逐条输出 PAC。没有完成其原生大规模匹配耗时与内联 provider 版本兼容验证，不能把配置生成耗时或规则数量推导为每连接性能结论。原生 domain rule-provider 的分段合并需要单独保持动作与规则顺序。

验收状态修正：Rust 决策模型的穷举证明仅覆盖该模型；批次长度测试不是跨类型决策等价证明。真实内核的全部域名边界、混合类型重叠、DNS/嗅探差异仍需专门实流对照，不能从模型通过推断全部完成。
