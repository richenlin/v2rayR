# 应用条件与分流策略

发行版当前采用本文末尾的「TUN 规则分流」路线。前面的透明代理内容记录已完成的原型及其边界。

规则分流沿用现有规则表。每条规则增加「应用」，缺省为 `*`。指定多个程序时，任意一个身份匹配且目标条件匹配才执行该行。按优先级取首条命中。身份未知继续匹配后续规则。旧域名、IP、Geo 和进程规则保留原语义。现有内置规则优先级在兼容迁移前保持各内核原行为。

## 应用录入

从系统文件选择器选择应用包或可执行文件。主程序与相关 Helper 分别确认，保存后逐个匹配。显示名称仅用于展示。macOS 正式接管应以系统提供的审计身份验证签名要求，路径可用于区分安装副本。无稳定签名的程序绑定规范化路径和文件指纹。Windows 正式接管使用 WFP 提供的应用身份，按需校验路径及签名。父子关系只用于推荐，不能扩大匹配范围。无法归属的共享进程按未知来源处理。

存储层为现有规则追加应用字段。缺少字段的旧规则和备份视为 `*`。跨机器恢复保留原身份，找不到对应应用时由用户重新绑定，避免按名称重绑。含本机路径的备份需要明确说明该字段会被导出。

## 接入与出口

只有规则分流执行应用条件。全局和直连跳过规则表。TUN 固定全局代理，退出后恢复之前的策略。防回环规则优先。系统代理与手动代理入口的普通请求可能缺少源应用身份。PAC 返回直连的请求不会进入普通代理入口。

macOS 使用签名的 Network Extension 透明代理系统扩展采集来源和目标。Windows 使用签名的 WFP 组件。接入组件与节点内核分离，并保留 TCP 目标和每个 UDP 数据报的目标及回包对应关系。明确命中代理且转发失败时返回错误。系统 DNS 与业务连接分别验收。接入未就绪时，规则编辑器应展示状态，运行时不得把指定应用规则降级为任意应用规则。若当前实现完全没有来源识别能力，启用指定应用规则后应明确拒绝启动规则分流会话，直到用户停用该规则或接入就绪。

## 验收

先验证旧库迁移、备份、主程序和 Helper 独立选择及同名程序身份隔离。macOS 实机使用可控 TCP 和 UDP 服务确认两个同名应用的出口，验证选中的 Helper 独立命中、未选成员回落、TCP 和 UDP 双栈、同一 UDP 套接字多目标、HTTP/3、TUN 跳过、停止和强杀恢复。应用身份录入测试与实际接管测试分开记录。Windows 交付签名测试包，由用户实机测试。

## 当前实现进度

- 规则表可录入应用，旧规则默认 `*`。桌面文件选择器解析 macOS 应用包的主程序以及包内的 Helper 应用和 XPC 服务。当前保存真实路径和 SHA-256，显示名称不参与身份判定。运行时签名身份仍需与平台接入组件一起实现。
- SQLite 迁移及备份可保留应用字段。当前启用指定应用规则会拒绝启动规则分流会话并提示原因，防止规则被错误执行。TUN 使用全局代理。
- macOS 本机已验证两个同名测试应用包、独立 Helper 和同路径替换程序的身份差异。验证覆盖录入和持久化。透明代理扩展、Windows WFP、TCP/UDP 出口验收及签名安装包尚未完成。

### macOS 接管原型

原型位于 `apps/macos-transparent-proxy`，最低目标为 macOS 15。扩展从流元数据读取审计令牌，经 Security 框架验证运行进程与磁盘签名对应，再匹配已录入的规范化路径和 SHA-256。Helper 独立匹配。能识别进程但找不到录入身份时使用匿名规则身份，来源进程完全无法归属时暂由系统处理，以避免把内核自身的出站重新接入。后一项需要安装后重点验证。

应用层从数据库的一份快照读取启用规则并生成会话凭证。`v2rayr_config::application_ingress::emit` 在现有 sing-box 配置中生成独立的回环认证 SOCKS 入口，把每条应用条件转换为仅在该入口生效的认证身份限制。保留原有规则顺序、目标条件和最终出口。普通入口不能选择应用身份。原型 TCP 使用 CONNECT，UDP 为每个目标单独建立 UDP ASSOCIATE，保留数据报目的地址及回包来源。全局和 TUN 不启用此配置。扩展配置通过启动选项传入，包含会话凭证，不写入长期系统代理配置。

在 macOS 上用匹配 Swift 编译器的 SDK 构建原型可执行文件。例如 Swift 6.1.2 可选用本机 macOS 15.5 SDK。

```sh
xcrun swiftc -sdk /Library/Developer/CommandLineTools/SDKs/MacOSX15.5.sdk \
  -target arm64-apple-macosx15.0 apps/macos-transparent-proxy/*.swift \
  -o /tmp/v2rayr-transparent-proxy
cargo test -p v2rayr-config --lib application_ingress_preserves
```

本地验收使用运行中测试程序的真实审计令牌验证同名程序和 Helper 匹配，并通过 Swift SOCKS 客户端、随包 sing-box 和可控回显服务验证 TCP/UDP 的代理、直连及阻止。该测试没有安装或启用系统扩展，也没有覆盖系统交付审计令牌、桌面会话绑定、PAC 共存、停止恢复或真实节点出口。桌面仍保留应用规则启用检查，等待扩展部署和会话集成。Xray、Mihomo 与 Windows 仍待实现。

## 当前交付路线：TUN 规则分流

发行版以已有管理员授权 TUN helper 为接管入口。透明代理扩展原型留作研究，发行版应用分流不依赖该扩展及其签名。macOS 的 TUN 提供「全局代理」与「规则分流」，默认仍为全局。非 TUN 策略独立保存。其他平台先保留全局 TUN，等平台实测再开放规则分流。

TUN 规则分流使用同一张启用规则表，按表格顺序首条命中。应用默认 `*`，指定多个路径时任一匹配，并与目标条件取交集。代理交给现有本地节点，直连由 TUN 桥从当前物理网卡发出，阻止则拒绝。无命中默认直连。DNS 接管、回环和节点地址绕行优先。应用的业务直连仍可能经过 TUN，系统 DNS 仍使用现有 DoH 策略。节点内核在规则分流时只承担代理出口，不重复执行规则表。

首版支持精确域名、域名后缀、IP 网段，以及应用规则的任意目标。应用选择器保留主程序与 Helper 的独立选择。旧进程名和 Geo 类型在此接入路径没有对应的可靠匹配或可信规则集时，连接前提示用户停用相应规则。助手只接受有大小上限的结构化规则，禁止传入任意内核配置和资源文件路径。可执行文件的完整路径精确匹配，启动前由非特权进程核对保存的 SHA-256。运行期间的同路径替换与连接级文件身份验证属于后续工作。来源查找失败时不会匹配指定应用行，后续通配规则仍可匹配。

验收区分内核配置校验和实际 TUN 接管。同名程序、选中与未选中的 Helper、TCP、连接型及非连接型 UDP、IPv4/IPv6 和网络切换后直连出口须分别记录。保留既有 DNS、断开和强杀恢复验收。Windows 实机由用户验证。

### macOS 本机实测

2026-11-10，在 macOS ARM64 部署新版 helper，使用 sing-box 1.14.4。两个同名、内容相同但路径不同的测试程序、独立 Helper 和未选更新器访问可控 SOCKS 节点或外部直连目标。根据应用收到的响应和测试节点记录核对出口。TCP、连接型 UDP 和非连接型 UDP 的 12 项对照通过。单个 UDP 套接字发往两个目标的测试发现第二个目标错误沿用了首个目标的出口。修复版将 UDP 映射按目标地址和端口拆分，同一套接字的代理与直连出口复测通过。指定应用的 UDP 阻止规则也通过对照，合计 14 项。

正常关闭和强杀测试控制进程后，本轮 utun、临时 DNS 和探测目标路由均恢复。规则模式下观察到系统解析发起到 DoH 的 SOCKS 连接，但测试出口直连 DoH 上游超时，未验收解析成功或无泄漏。双栈直连、切换网络、桌面界面和 Windows 留待单独验证。

同日复验：经现有本机 SOCKS 节点接通真实 DoH 上游后，三个随机域名通过系统默认解析成功。受控 IPv6 TCP 和 UDP 均通过 TUN 到达 SOCKS 测试节点并收到回包。本机物理网卡无 IPv6 默认路由，IPv6 互联网直连待验收。物理网卡明文 DNS 抓包未获得授权，本轮没有无泄漏结论。

桌面使用隔离数据目录与内嵌前端，验证 TUN 默认全局、可切换规则、退出 TUN 后恢复非 TUN 策略。通过原生文件选择器保存独立 Helper 规则并验证表格中的应用值。首次从界面连接时，规则模式的外部 HTTP 探测失败导致回滚。现已将规则模式的启动判据改为节点探测成功和 TUN 路由读回成功，外部 HTTP 探测继续用于全局模式。修复后的桌面版已实际连接、解析和断开，路由恢复到物理网卡，临时 DNS 已清除。原生测试分别验证代理探测目标、规则阻止探测目标和全局模式。Wi-Fi 当时关闭，未进行网络切换。

规则模式网络切换复验：同一 TUN 租约保持运行，将系统默认网卡从 Ethernet（en0）切到 Wi-Fi（en1）再切回。三阶段分别用 TCP 和 UDP 对照验证应用代理与未命中直连，共 12 项通过，临时 DNS 配置在会话内持续存在。断开后清除 TUN 和临时 DNS，恢复原有网络服务顺序与 Wi-Fi 电源状态。此项覆盖切换后的新流量。

明文 DNS 复验：在 Ethernet（en0）限定 TCP/UDP 53 抓包。启用 TUN 前的校准查询可见。规则模式内三个随机域名均由系统默认解析得到预期响应，并观察到经 SOCKS 连接 DoH 上游。三个测试域名在物理网卡明文抓包中均无记录。结论限定于该接口、该窗口和这三个查询。抓包进程已退出，临时 DNS 和 TUN 均已清理。

## 系统代理与 PAC

系统代理的“规则”策略使用本地 PAC 服务，不再单列“PAC 自动代理”接入方式。防回环和配置的绕过项优先，其后按自定义域名/IP 规则顺序匹配，再匹配下载的 PAC 规则；下载列表未命中时直连。阻止动作交给本地代理内核拒绝。指定应用的身份匹配仍需要 TUN，PAC 不具备源应用识别能力。尚未下载有效 PAC 列表时，未命中自定义规则的请求进入本地代理，由内核规则处理。全局和直连策略使用固定系统代理入口，不读取 PAC 列表。旧 `pac` 接入值兼容映射为 `system-proxy`。
